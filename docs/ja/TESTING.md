# テスト方針とガイド (TESTING.md)

このドキュメントでは、`MyBunka` の自動テスト方針、テストケースの分類、および手動検証手順について説明します。

---

## 1. 自動テスト方針

本プロジェクトでは、リファクタリングや機能追加時における品質の維持（回帰テスト）を目的として、単体テストを厳約して維持しています。

### 1.1 コアロジック単体テスト (`src/lib.rs`)

- `src/lib.rs` の `tests` モジュールに、コアロジックの単体テストを配置しています。
- 主なテスト対象：
  - 代表的な有理数・無理数近似（`0.142857 -> 1/7`, `0.5 -> 1/2`, `3.14159265 -> 355/113` など）
  - パーセント表記のパース（`10% -> 0.1`, `  -5.5 %  -> -0.055` など）
  - ゼロ・負数・最大分母境界条件の検証
  - ドキュメントテスト（doctest）による公開関数の使用例検証

### 1.2 CLI引数解析単体テスト (`src/cli.rs`)

- `src/cli.rs` の `tests` モジュールに、コマンドライン引数解析の単体テストを配置しています。
- 主なテスト対象：
  - 基本的な引数（小数値・パーセント表記）のパース
  - オプション引数（`-d`, `--max-den`, `-t`, `--tolerance`）の解析とデフォルト値
  - ヘルプ（`-h`, `--help`）およびバージョン（`-v`, `-V`, `--version`）フラグの判定
  - 異常系引数（値の欠落、不正な文字列など）のエラーハンドリング

---

## 2. ローカルでのテスト実行

PowerShell 7 (pwsh) で以下のコマンドを実行して、テストを検証します：

```powershell
# 単体テストの実行
cargo test

# Clippy による静的解析（警告をエラー化）
cargo clippy --all-targets -- -D warnings

# フォーマットチェック
cargo fmt --check

# Rustdoc ドキュメントビルドチェック
cargo doc --no-deps --document-private-items
```

※ Markdown ファイル（`.md`）のみの修正時は、上記のローカルテストおよび事前検証プロセスの実行はスキップ可能です。
