# システム仕様書 (SPEC.md)

このドキュメントでは、`bunka` のソフトウェア要件、インターフェース定義、およびアルゴリズムの詳細仕様について説明します。

---

## 1. CLI システム仕様

### 1.1 インターフェース定義
本ツールはコマンドラインインターフェース（CLI）で動作し、引数に変換対象の小数点数（またはパーセント表記）とオプションパラメータを指定できます。

- **コマンド構文**:
  - 数値変換時: `bunka <数値またはパーセント表記> [オプション]` （例: `bunka 0.142857` / `bunka 10%`）
  - バージョン表示時: `bunka --version` (または `-v`, `-V`)
  - ヘルプ表示時: `bunka --help` (または `-h`)
- **標準出力 (stdout)**:
  - 数値変換時: 既約分数の形式 `<分子>/<分母>` （例: `1/7`, `1/10`）で出力されます。
  - バージョン表示時: `bunka <バージョン番号>` （例: `bunka 0.5.0`）で出力されます。
  - ヘルプ表示時: 使用方法、引数、オプション、使用例を含むヘルプメッセージが出力されます。
- **標準エラー出力 (stderr)**: 実行失敗時、または引数が無効な場合にヘルプや警告を出力します。
- **終了コード (Exit Codes)**:
  - `0`: 変換成功、バージョン情報表示成功、またはヘルプ表示成功。
  - `1`: 変換失敗（引数不足、または無効な数値・パーセント表記、未知のオプション指定）。

### 1.2 パラメータオプション一覧
CLIの引数の後ろに以下のパラメータを指定して、分数近似アルゴリズムの制御上限を変更することができます。

| オプション（ロング） | オプション（ショート） | 値の型 | デフォルト値 | 役割 |
| :--- | :--- | :--- | :--- | :--- |
| `--max-den` | `-d` | 正の整数 (`u64`) | `100,000` | 近似計算に使用する最大分母。 |
| `--tolerance` | `-t` | 正の浮動小数点数 (`f64`) | `1e-6` | 近似計算の許容誤差しきい値。 |

#### コマンド指定例:
```bash
$ bunka 0.142857 -d 1000 -t 1e-4
1/7
```

### 1.3 アルゴリズム仕様（連分数展開）
実数 $x$ を分数 $h/k$ に近似するために、`bunka` は**連分数展開（Continued Fraction Expansion）**アルゴリズムを採用しています。

1. **符号の処理**: 入力値の符号を判定・抽出します。絶対値 $|x|$ に対して分数を算出し、最終的に元の符号を分子に乗算します。
2. **展開ループ**:
   - 残差 $r_n$（初期値は $|x|$）の整数部分を $a_n$ とします。
   - 以下の漸化式を用いて近似分数の数列（近似分数）を動的に計算します：
     $$h_n = a_n h_{n-1} + h_{n-2}$$
     $$k_n = a_n k_{n-1} + k_{n-2}$$
     ここで初期状態は $(h_{-1}, k_{-1}) = (1, 0)$ および $(h_{-2}, k_{-2}) = (0, 1)$ と定義されます。
3. **終了判定**:
   - 計算された分母 $k_n$ が最大許容分母 $max\_denominator$ を超えた場合、ループを終了し、手前の近似分数 $h_{n-1}/k_{n-1}$ を採用します。
   - 対象値 $x$ と現在の近似値 $h_n/k_n$ の絶対誤差が許容誤差 $tolerance$ 以下になった場合、即座にループを終了します。
   - 残差の小数部分（$r_n - a_n$）がほぼゼロ（`10^-11` 未満）になった場合、ループを終了します。
   - ループ回数が `50` 回に達した場合、異常ループ防止のため強制終了します。
   - 残差を更新します： $r_{n+1} = 1 / (r_n - a_n)$。

### 1.4 数値入力パース仕様
本ツールでは、通常の小数点表記（例: `0.142857`）の他に、パーセント表記（例: `10%`）の入力もパース可能です。パースの処理手順は以下の通りです：

1. **空白のトリミング**: 入力された文字列の前後の空白をトリムします。
2. **パーセント記号の判定**: トリム後の文字列が文字 `%` で終了しているかを判定します。
3. **パースと除算**: 
   - 末尾が `%` の場合、`%` を除いた部分を再度トリムし、浮動小数点数（`f64`）としてパースした後に `100.0` で除算した値を算出します（例: `10%` は `0.1` へ、`  -5.5 % ` は `-0.055` に変換）。
   - 末尾が `%` でない場合、通常の浮動小数点数としてパースします。
4. **エラーハンドリング**: いずれのパースにおいても無効な数値形式（例: `abc` や `10%%`）の場合はエラーとなり、処理を中断します。

## 2. 開発およびリリース・運用仕様

### 2.1 開発用エディタ設定
プロジェクト全体のコード品質および書式を一貫させるため、以下の設定ファイルを適用しています。
- **[.editorconfig](../../.editorconfig)**: 改行コードを `LF`、文字コードを `UTF-8 (BOMなし)`、インデント幅を `4`（Markdown/YAML等は `2`）に統一します。
- **[.vscode/settings.json](../../.vscode/settings.json)**: VS Code 利用者向けに、保存時の自動整形（rustfmt）の有効化、インデントおよび文字コード設定を共有します。

### 2.2 CI/CD および自動リリース仕様
- **継続的インテグレーション (CI)**:
  - プッシュおよびプルリクエスト発生時に Windows 環境で自動ビルドと `cargo test` を実行し、コードの健全性を保ちます（[.github/workflows/ci.yml](../../.github/workflows/ci.yml)）。
- **継続的デプロイ (CD) および自動リリース判定**:
  - `main` ブランチへのプッシュ（またはプルリクエストのマージ）時に、ワークフローが自動でトリガーされます（[.github/workflows/release.yml](../../.github/workflows/release.yml)）。
  - `Cargo.toml` の `version` を自動的に読み込み、リモートリポジトリ上の既存の Git タグと照合します。
  - まだリリースされていない新バージョンの場合に限り、自動で Git タグを生成・プッシュし、GitHub Release の作成を行います。
  - Windows 向け CLI バイナリをリリースビルドし、zip アーカイブ（`bunka-windows-x64.zip`）にまとめて GitHub Releases に自動デプロイします。このパッケージング処理は `target/release` ディレクトリ内で完結するように構成されています。

### 2.3 依存関係の自動更新
- **[dependabot.yml](../../.github/dependabot.yml)**:
  - GitHub Actions の Action バージョンおよび Cargo の依存ライブラリを週次で監視し、更新プログラムがある場合は自動的にプルリクエストを作成します。
