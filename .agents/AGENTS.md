# AI Agent Instructions for MyBunka

本プロジェクトにおける大賢者の開発指示書です。
最優先ルール（コミット禁止・テーブル整列等）は [GEMINI.md](../GEMINI.md) を参照してください。

## 🎯 開発・品質ルール

- **コミットメッセージ規約**:
  - ボスからコミットの指示を受けた際、コミットメッセージは**日本語**で記述すること。
  - 先頭の種別プレフィックス（`feat:`, `fix:`, `chore:`, `docs:`, `refactor:` 等）は英語を使用してよい。
- **技術解説・対話方針（他言語経験に配慮）**:
  - ユーザーは他言語での開発経験をお持ちですが、**Rust、React、TypeScript などの固有の言語仕様・専門用語（所有権、ライフタイム、トレイト、フック等）には不慣れ**です。
  - 修正内容や設計の説明を行う際は、難解な言語固有用語を直接多用せず、一般的・共通的なプログラミング概念（参照、インターフェース、モジュール、関数など）に置き換えるか、直感的に理解できるよう分かりやすく補足・解説を添えること。
- **事前検証とドキュメント同期**:
  - 開発およびドキュメント更新の際は、必ず [`docs/ja/INSTRUCTIONS.md`](../docs/ja/INSTRUCTIONS.md) に記載されている「対象ファイルと更新要件一覧」および「品質管理・ローカル事前検証ルール」に厳格に従って検証・同期を行うこと。
  - **Markdownのみ修正時の検証省略**: ドキュメント等の `.md` ファイルのみを編集・修正する場合は、Rustの事前検証（`cargo fmt` / `cargo check` / `cargo test` / `cargo clippy` / `cargo doc` 等）をすべて省略し、迅速に対応・完了すること。
- **コード規模とリファクタリング**:
  - 単一のソースファイル（`src/main.rs` 等）のコード行数が **1,000 行** を超過した場合、サブモジュールへの分割リファクタリングを積極的に提案・推進すること。
